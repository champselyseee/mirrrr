  ДЕПЛОЙ НОВОГО ФРОНТЕНДА (frontend-react) НА VERCEL
  Telegram WebApp для проверки работ ЕГЭ
══════════════════════════════════════════════════════════════════════════════

Это инструкция по выкладке нового React-фронта (папка frontend-react/) вместо
старого статического index-9.html. Бэкенд (Railway, backendmirrr/bot.py) и его
эндпоинты НЕ меняются — фронт общается с тем же API.


────────────────────────────────────────────────────────────────────────────
0. ЧТО ВООБЩЕ ИЗМЕНИЛОСЬ В СТРУКТУРЕ ПРОЕКТА
────────────────────────────────────────────────────────────────────────────

Было:  frontend/index-9.html         — один статический HTML-файл
Стало: frontend-react/               — Vite + React + TypeScript проект

  frontend-react/
  ├── index.html              ← входной шаблон Vite (НЕ старый бот, см. ниже)
  ├── package.json            ← зависимости и команды (build/dev)
  ├── vite.config.ts          ← конфиг сборщика
  ├── vercel.json             ← настройки Vercel (framework, rewrites)
  ├── tsconfig*.json          ← конфиги TypeScript
  ├── .env.example            ← пример переменной VITE_BACKEND_URL
  ├── DEPLOY_FRONTEND.txt      ← этот файл
  ├── src/
  │   ├── main.tsx            ← точка входа
  │   ├── App.tsx             ← стейт-машина экранов + сабмит
  │   ├── index.css           ← дизайн-токены, шрифты, фон, анимации
  │   ├── lib/                ← логика: api, parse, image, config, telegram,
  │   │                          types, workTypes, demo (demo только для dev)
  │   └── components/         ← React-компоненты (экраны + UI)
  └── dist/                   ← РЕЗУЛЬТАТ СБОРКИ (npm run build), его и деплоим

ВАЖНО: frontend-react/index.html — это НЕ телеграм-бот и НЕ старый index-9.html.
Это служебный HTML-шаблон Vite, в который монтируется React (<div id="root">).
Шрифты и весь дизайн подключены внутри src/, а не здесь.

Старую папку frontend/ можно оставить как архив или удалить позже — на новый
деплой она не влияет.


────────────────────────────────────────────────────────────────────────────
1. ЛОКАЛЬНАЯ ПРОВЕРКА ПЕРЕД ДЕПЛОЕМ (необязательно, но желательно)
────────────────────────────────────────────────────────────────────────────

В терминале:

  cd frontend-react
  npm install          # поставить зависимости (только первый раз)
  npm run build        # собрать прод-версию в dist/

Если build прошёл без ошибок — всё готово к выкладке.
Посмотреть локально собранную версию: npm run preview


────────────────────────────────────────────────────────────────────────────
2. ПЕРЕМЕННАЯ ОКРУЖЕНИЯ (адрес бэкенда)
────────────────────────────────────────────────────────────────────────────

Фронт по умолчанию ходит на:
  https://boooot-production-6bee.up.railway.app
(этот адрес зашит в src/lib/config.ts как дефолт — совпадает со старым фронтом).

Если адрес Railway-сервиса ДРУГОЙ — задай переменную окружения при сборке:

  VITE_BACKEND_URL = https://ТВОЙ-railway-адрес.up.railway.app

На Vercel это задаётся в Settings → Environment Variables (см. шаг 3).
Если адрес тот же, что в дефолте — переменную можно НЕ задавать.


────────────────────────────────────────────────────────────────────────────
3. ДЕПЛОЙ НА VERCEL
────────────────────────────────────────────────────────────────────────────

Есть два пути. Выбери ОДИН.

╔══════════════════════════════════════════════════════════════════════════╗
║ ВАРИАНТ A — через сайт Vercel + GitHub (рекомендуется, авто-деплой)        ║
╚══════════════════════════════════════════════════════════════════════════╝

  1) Залей frontend-react/ в GitHub-репозиторий (или подпапкой в существующий).

  2) На vercel.com → Add New → Project → выбери этот репозиторий.

  3) В настройках импорта:
     • Root Directory: укажи  frontend-react
       (ВАЖНО, если репозиторий содержит и бэкенд — Vercel должен собирать
        именно папку фронта)
     • Framework Preset: Vite (определится автоматически)
     • Build Command:    npm run build   (по умолчанию)
     • Output Directory: dist            (по умолчанию)

  4) (Опционально) Environment Variables → добавь VITE_BACKEND_URL, если адрес
     Railway отличается от дефолтного (см. шаг 2).

  5) Deploy. Через ~1 минуту получишь URL вида https://ИМЯ.vercel.app

  Дальше каждый git push в main будет автоматически пере-деплоить фронт.

╔══════════════════════════════════════════════════════════════════════════╗
║ ВАРИАНТ B — через Vercel CLI (без GitHub, быстрый разовый деплой)          ║
╚══════════════════════════════════════════════════════════════════════════╝

  1) Установить CLI (один раз):     npm i -g vercel
  2) Войти:                          vercel login
  3) Из папки фронта:
       cd frontend-react
       vercel            # первый раз — ответить на вопросы (привязка проекта)
       vercel --prod     # выложить в продакшн, получить финальный URL

  Если адрес бэкенда другой — задай переменную перед прод-деплоем:
       vercel env add VITE_BACKEND_URL production
     (вставь адрес Railway), затем снова  vercel --prod


────────────────────────────────────────────────────────────────────────────
4. ГЛАВНЫЙ ШАГ ПОСЛЕ ДЕПЛОЯ — СВЯЗАТЬ БОТА С НОВЫМ ФРОНТОМ
────────────────────────────────────────────────────────────────────────────

Бот открывает WebApp по адресу из переменной окружения WEB_APP_URL (Railway).
Чтобы кнопка в боте вела на НОВЫЙ фронт:

  ВАРИАНТ 1 (проще всего, без правок бота):
    При деплое на Vercel привяжи фронт к тому же домену, что использовался
    раньше (например mirrrr.vercel.app). Тогда WEB_APP_URL менять НЕ нужно.

  ВАРИАНТ 2 (новый домен):
    1) Зайди в Railway → проект бэкенда (backendmirrr) → вкладка Variables.
    2) Найди переменную  WEB_APP_URL
    3) Поставь новый адрес фронта БЕЗ слэша в конце и БЕЗ ?token=, например:
         WEB_APP_URL = https://ИМЯ.vercel.app
       (бот сам допишет ?token=... при формировании кнопки)
    4) Сохрани — Railway перезапустит бэкенд автоматически.

  ⚠️ В Telegram WebApp работает ТОЛЬКО по HTTPS. Vercel выдаёт HTTPS сразу —
     ничего дополнительно настраивать не нужно.


────────────────────────────────────────────────────────────────────────────
5. ПРОВЕРКА, ЧТО ВСЁ РАБОТАЕТ
────────────────────────────────────────────────────────────────────────────

  1) Открой бота в Telegram, отправь /start
  2) Нажми кнопку «✍️ Открыть проверку»
  3) Должна открыться новая (Risograph) форма:
       — выбери тип работы
       — вставь текст (или приложи фото/файл)
       — нажми «Отправить на проверку»
  4) Через 1–3 минуты появится экран результата с баллом и разбором.

  Если открывается экран «Нет доступа»:
    — это нормально, если токен истёк (TTL 2 часа) или уже использован.
      Нажми /start в боте заново, чтобы получить свежую кнопку.
    — если стабильно не пускает у всех — проверь, что WEB_APP_URL в Railway
      указывает на правильный домен и фронт реально открывается по этому URL.

  Если «Сервер не отвечает»:
    — Railway мог уйти в cold start. Подожди 30–60 сек и нажми кнопку снова.
    — Проверь, что BACKEND_URL/VITE_BACKEND_URL указывает на живой Railway.


────────────────────────────────────────────────────────────────────────────
6. КОНТРАКТ С БЭКЕНДОМ (для справки — менять не требуется)
────────────────────────────────────────────────────────────────────────────

Фронт использует те же эндпоинты, что и раньше:
  GET  /check_token?token=...                 → { ok: true|false }
  POST /proxy  { token, type, text, photos[], file }  → { answer }
  POST /ocr    { token, photo }               → { text }   (распознавание рукописи)

Новое по сравнению со старым фронтом:
  • Задействован эндпоинт /ocr — кнопка «Распознать текст с фото» под фото.
    Токен при OCR НЕ сжигается (как и предусмотрено в bot.py).
  • Баллы по критериям теперь показываются по правильной шкале каждого типа
    (email: К1–К3 из 2; essay: К1–К4 из 3, К5 из 2; composition: К1–К10 по шкале).

Никаких изменений в bot.py или в базе данных НЕ требуется.


────────────────────────────────────────────────────────────────────────────
7. DEV-РЕЖИМ (для разработки, в продакшн не попадает)
────────────────────────────────────────────────────────────────────────────

  npm run dev               → локальный сервер http://localhost:5173
  • Без токена в dev сразу открывается форма (в проде — экран «Нет доступа»).
  • ?demo=1 / ?demo=email / ?demo=composition — показать пример экрана
    результата без бэкенда. Эти демо-данные вырезаются из прод-сборки
    (обёрнуты в import.meta.env.DEV), в Vercel-бандл не попадают.
